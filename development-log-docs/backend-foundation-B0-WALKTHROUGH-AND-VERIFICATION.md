## 2. Bugs and gaps found along the way (fixed)

| #   | Finding                                                                                                                                 | Fix                                                                                                               |
| --- | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 1   | **Patients could read and change the voice-agent config and list every voice call** (caller phones + transcripts)                       | `/voice-agent/*` limited to staff; config writes limited to SUPER_ADMIN. Locked in by the authZ matrix            |

| 4   | `withTenantBypass('x', () => prisma.y.findFirst())` silently ran **outside** the bypass (Prisma queries are lazy)                       | `runInScope` starts returned thenables inside the scope                                                           |
| 5   | Guard log lines dumped query arguments (names, emails) to logs                                                                          | keys only                                                                                                         |
| 6   | Developers' personal Gmail addresses + a hard-coded password in dev scripts                                                             | replaced with synthetic values; `set-password.ts` requires env                                                    |
| 7   | Database built from migrations alone drifted from the schema (missing column, FKs)                                                      | idempotent `20261013000000_reconcile_schema_drift` (no-op on Neon)                                                |
| 8   | 16 pre-existing unit tests failing (ESM export patching, stale mocks)                                                                   | fixed. Whole suite green                                                                                          |
| 9   | Backend high/critical advisories (proxy-addr **critical**, multer, nodemailer, express-rate-limit/ip-address, AWS SDK, ws, prisma deps) | upgraded / pnpm overrides. One dated exception (`braces` via nodejs-whisper, no patched release; removed by B2.1) |

| 11  | Booking transaction read the membership discount outside the transaction                                                                | uses the `tx` executor                                                                                            |

**Open product decisions found (not B0 blockers):** (a) a patient with no home clinic joining a waitlist at a clinic they aren't a member of now gets 403 (no membership is created). (b) The patient-overlap check on staff-made bookings now only sees the staff clinic; a cross-clinic check would have to run outside the booking transaction.

```bash
# Postgres 18 + Redis (ports chosen to avoid Windows-reserved ranges)
docker run -d --name mf-pg -e POSTGRES_PASSWORD=postgres -p 55432:5432 postgres:18
```

## 7. Known limits / follow-ups

- **MFA and idle-logoff UX** are frontend tasks F0.2.1/F0.2.2. The backend is ready.
- Security-monitor counters live in memory per instance. If the API scales beyond one instance, move them to Redis.
- Rate limits are in memory per instance (same caveat).
- Patient-existence check (F-1) and anonymous hold `patientId` (F-2): see docs/PUBLIC_ROUTE_SCOPING.md.
- Redis today is `redis://` (no TLS) on the free Redis Cloud tier. Switch to `rediss://` on a paid plan before real data (the code supports it).
- The integration database keeps audit rows between runs by design (append-only). Recreate `mf_it` to start clean.
